Guides et senseurs du dépôt

Un guide oriente le travail avant ou pendant la production. Un senseur observe le code ou son comportement et renvoie un résultat. Voici les mécanismes repérés dans Gesta, classés selon leur nature.

Inférentiel : consigne ou retour interprété par une personne ou une IA.
Computationnel : règle appliquée ou résultat produit par un outil exécutable.

Exemple : permissions.test.ts vérifie qu’un contact promoteur/signataire ne peut pas lister les offres (false), tandis qu’un étudiant y est autorisé (true).

Un guide n’est pas nécessairement exécutable

AGENTS.md oriente le raisonnement de l’agent ; son application dépend de l’interprétation du texte par celui-ci. Le fait de consulter le guide ne prouve pas automatiquement le respect de toutes ses consignes.

Un senseur n’explique pas toujours la correction

Tests, lint, types et build produisent des signaux reproductibles, mais les diagnostics demandent souvent une interprétation pour choisir la correction.

Inventaire fondé sur les fichiers et commandes visibles dans le dépôt au moment de l’exploration. Une case vide signifie qu’aucun mécanisme correspondant n’a été repéré, non que ce type de mécanisme serait impossible.
